How to edit sources (non-technical guide)

Pause or resume a source

  1. Click Edit sources.yaml on GitHub above, then the pencil icon.
  2. Find the source by its name: line.
  3. Change enabled: true to enabled: false (or back).
  4. Click Commit changes. Done — the next refresh respects it.

Point a source at a new URL (e.g. the City moves a page)

  1. Edit the file the same way and replace the url: value.
  2. Commit. Nothing else needs to change.

Add a new dataset from any open-data portal

Copy this block to the bottom of the file, fill in the three CAPITALIZED parts, and commit:

  - id: my_new_dataset
    name: HUMAN-READABLE NAME
    category: business_activity     # or employment / real_estate / city_finance
    type: socrata
    enabled: true
    schedule: daily
    output: my_new_dataset.json
    params:
      domain: data.oaklandca.gov    # or data.acgov.org, data.ca.gov, ...
      dataset_id: ABCD-1234         # from the dataset's "API" button
      soql: "$limit=20000"
      date_field: DATE_COLUMN_NAME  # enables an automatic monthly trend chart

For new kinds of sources (a different PDF format, a new publisher), a developer adds a small fetcher in pipeline/fetchers/ — the registry pattern keeps that a one-file change.

Verification checklist (first run)

  • BLS series IDs — confirm the two LAUS/CES series IDs in sources.yaml at data.bls.gov/series-report. If a series is wrong, the table above will show a warning after the first run; paste the corrected ID.
  • Optional keys — add repository secrets BLS_API_KEY (free, higher limits) and FRED_API_KEY (only if you enable FRED sources).
  • Publisher courtesy — CBRE and Cushman & Wakefield pages are scraped gently (one page per quarter, cached). If they block automated access, figures can be entered by hand in the data JSON, or sourced via a research subscription.
